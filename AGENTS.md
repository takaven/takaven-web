# Website repository agent instructions

**This repository is the static marketing source only:** `takaven/takaven-web`. Product application: `takaven/teamframe`. The old `takaven/teamframe-site` is a superseded commercial-site source awaiting explicit retirement, not a source to merge automatically.

Before work: read `README.md`, `docs/WEBSITE-OPERATIONS.md`, `docs/LEGACY-CONSOLIDATION.md` and the current application `TEAMFRAME_MANAGED_PEOPLE_OPS_SCOPE.md`, `TEAMFRAME_ACCESS_MODEL.md`, `docs/operations/CURRENT-STATE.md` and `docs/launch/DECISIONS.md`. Resolve dated status against the relevant live provider before asserting current deployment state.

- Preserve approved site design, assessment and marketing language unless change is bounded and evidenced.
- Do not import old prices, support SLAs, payroll processing, customer data or product features simply because an old webpage mentions them.
- Do not edit TeamFrame application code, app Vercel/Supabase, GitHub repository protection, domain DNS or public deployment outside separately authorised scope.
- Source changes use short-lived branches and PRs; Vercel may auto-deploy on merge.
- Every material change must update one canonical operations document; avoid parallel trackers and duplicate copies of product scope.
- Distinguish **verified live**, **dated reported**, **pending**, and **historical**; never describe `www.takaven.com` as live without checking.
- Removing an old repo is a separate explicit decision after registry/source references are reconciled.
